# MiniLaunch

~/Apps에 정리한 앱들을 반투명 Grid로 여는 macOS 네이티브 런처입니다.
Finder alias와 하위 폴더가 곧 앱 구성입니다.

## 빌드와 실행

macOS 13 이상과 Icon Composer를 지원하는 Xcode 26 이상의 빌드 도구가 필요합니다.
아이콘은 프로젝트의 icon.icon을 actool로 컴파일합니다. Command Line Tools만으로는 아이콘을 컴파일할 수 없습니다.
Xcode GUI를 열거나 개발자 계정에 로그인할 필요는 없습니다.

```sh
# Xcode 설치 후 초기 구성 요소를 설치하지 않은 경우 실행합니다.
sudo xcodebuild -runFirstLaunch

./build.sh
open dist/MiniLaunch.app
```

현재 Mac의 아키텍처로 빌드하며 dist/MiniLaunch.app을 생성합니다.
인증서를 요구하지 않는 로컬 ad-hoc 서명을 사용합니다.
인터넷 배포용 Developer ID 서명 및 공증은 포함하지 않습니다.

선택적으로 사용자 Applications 폴더에 설치하실 수 있습니다.

```sh
./build.sh --install
open ~/Applications/MiniLaunch.app
```

기존 설치가 있으면 덮어쓰지 않습니다. 앱을 종료한 뒤 기존 앱을 옮기고 다시 실행해 주세요.
Dock 고정은 실행한 앱의 Dock 메뉴에서 직접 설정하실 수 있습니다.

## 앱 구성

Finder에서 ~/Apps 폴더를 만들고 원하는 앱의 alias를 넣어 주세요.
실제 하위 폴더를 만들면 Grid 안에서 이동할 수 있습니다.
이미 ~/Apps가 있으면 그대로 사용하며 내용을 자동 수정하지 않습니다.

```text
~/Apps/
├── Safari
├── Notes
└── 개발/
    ├── Terminal
    └── Visual Studio Code
```

Finder의 '가상본 만들기'로 만든 파일과 심볼릭 링크를 지원합니다.
앱 번들 자체도 표시합니다. 이름순으로 정렬하며 깨진 alias는 흐리게 표시합니다.
다른 폴더로 시험하려면 앱을 종료하고 실행 인자를 지정해 주세요.

```sh
open dist/MiniLaunch.app --args -AppsDirectory "/절대/경로/Apps"
```

## 조작

| 입력 | 동작 |
| --- | --- |
| Dock의 MiniLaunch 클릭 | Grid 열기 |
| Dock 오른클릭 → Open ~/Apps | ~/Apps를 Finder로 열기 (별도 경로 설정 시 해당 폴더) |
| 앱 클릭 / Return | 선택한 앱 실행 |
| 폴더 클릭 / Return | 폴더 안으로 이동 |
| 방향키 | 선택 이동 |
| ⌘↑ / ‹ 버튼 | 상위 폴더 |
| ⌘R | 목록 다시 읽기 |
| Esc / 바깥 클릭 | Grid 닫기 |
| ⌘Q | 상주 프로세스 종료 |
| 네 손가락 또는 다섯 손가락 모으기 | 화면 중앙에 Grid 열기 |
| 네 손가락 또는 다섯 손가락 펼치기 | 열린 Grid 닫기 |

Dock 아이콘의 정확한 위치를 사용하려면 MiniLaunch 메뉴의
**Advanced → Allow Dock Position Access…**을 선택하고 시스템 설정에서 접근성 권한을 허용해 주세요.
권한 없이도 실행할 수 있습니다. 하단 Dock 영역에서 클릭한 경우에는 클릭 위치를 보조 기준으로 사용하며, 위치를 확인할 수 없으면 화면 중앙에 표시합니다.
하단 Dock에는 말풍선 꼬리를 표시하고, 좌우 Dock은 권한으로 확인한 아이콘 안쪽에 배치합니다. 좌우 방향의 꼬리는 아직 지원하지 않습니다.
위치 조회는 공개 [Accessibility API](https://developer.apple.com/documentation/applicationservices/axuielement.h)를 사용합니다.

## 제스처 제한

네 손가락과 다섯 손가락을 모두 지원합니다. 짧은 접촉 누락(120ms 이내)은 허용하며,
손가락 수 변화 자체를 모으기·펼치기로 판단하지 않도록 거리 기준을 보정합니다.
모아서 연 뒤 손을 떼지 않고 충분히 펼치면 닫을 수 있습니다. 같은 방향의 움직임과 작은 떨림은 중복 실행하지 않습니다.

2026-09-27 인식 개선은 합성 입력 테스트로 검증하며, 실제 트랙패드의 민감도와 사용감은 아직 실기 검증하지 않았습니다.

**Show Desktop 제스처의 조건부 차단은 아직 구현되지 않았습니다.**
네 손가락 또는 다섯 손가락 펼치기가 Grid를 닫아도 macOS의 Show Desktop이 함께 작동할 수 있습니다.
시스템 제스처 설정은 자동 변경하지 않습니다.

전역 네 손가락 또는 다섯 손가락 감지는 비공개 MultitouchSupport를 사용합니다.
[공개 AppKit 제스처 이벤트](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html)와 별개이며,
비공개 ABI는 [기존 구현의 선언](https://github.com/lauschue/Remotastic/blob/main/MultitouchSupport.h)을 참고했습니다.
OS 업데이트 후 동작이 달라질 수 있습니다.
메뉴의 'Advanced → Gesture Status…'에서 장치 등록 상태를 확인할 수 있으나,
등록 성공이 실제 프레임 수신이나 제스처 인식 성공을 뜻하지는 않습니다.

새 장치 연결 및 잠자기 복귀 후 필요하면 'Advanced → Reconnect Gesture Devices'을 선택해 주세요.
제스처 없이 실행하려면 앱 종료 후 다음 명령을 사용하실 수 있습니다.

```sh
open dist/MiniLaunch.app --args -DisableGestures YES
```

## Grid 디자인

첫 화면에는 제목 없이 Grid만 표시하며, 최대 6열과 128pt 셀 간격을 사용합니다.
하위 폴더에서는 폴더 이름과 뒤로가기 버튼을 표시합니다.
96pt 이미지 영역 안에 실제 앱 아이콘이 약 80pt로 표시되며 이름은 13pt입니다.
창은 항목 수에 맞춰 크기를 조절하고 화면보다 내용이 길면 스크롤합니다.
검색창과 상시 도움말은 표시하지 않으며 방향키 탐색은 유지합니다.
macOS 26 이상에서는 검정 50% 틴트를 적용한 NSGlassEffectView의 Clear Liquid Glass를 사용하고, 이전 버전에서는 기존 블러 재질을 사용합니다.
둥근 모서리와 하단 꼬리 마스크를 유지합니다.

Dock의 정확한 위치와 여러 모니터 배치는 아직 실기 검증하지 못했습니다.
이번 디자인 확인에서는 자동화 도구의 Dock 접근이 시간 초과되어,
실제 Dock 아이콘을 클릭한 배치 검증은 완료하지 못했습니다.

빌드 시 build/의 중간 산출물은 모두 재생성하며, 컴파일 성공 후 dist/MiniLaunch.app도 새로 조립합니다.
아이콘 원본은 icon.icon 하나만 관리합니다.


## Finder Tag 그룹

~/Apps 안의 alias 파일에 Finder Tag를 지정하면 Tag 이름순으로 그룹화합니다.
원본 앱의 Tag가 아닌 alias 자체의 Tag를 사용합니다.
각 그룹의 항목은 이름순이며, Tag 없는 항목은 마지막에 모읍니다.
그룹 제목은 표시하지 않고 새 행과 얇은 구분선으로 나눕니다.
Tag가 여러 개면 해당하는 각 그룹에 표시합니다.
다시 열거나 ⌘R을 누르면 변경된 Tag를 읽습니다.

창은 140ms로 살짝 튀어오르며 나타나고 90ms로 축소되며 닫힙니다.
macOS의 동작 줄이기가 켜져 있으면 짧은 페이드만 사용합니다.

등장 시작과 퇴장 끝에는 아이콘·텍스트에 짧은 Gaussian blur를 적용합니다. 전환 종료 후 필터를 제거하며 동작 줄이기에서는 생략합니다.


## 잠자기 이후 제스처 복구

시스템·화면 잠자기에서 깨어나거나 사용자 세션으로 돌아오면 1초 뒤 제스처 장치를 다시 연결합니다.
장치가 아직 없으면 2초 간격으로 최대 두 번 더 시도합니다. 겹치는 복귀 알림은 마지막 알림을 기준으로 처리합니다.
재연결 전에 대기 중이던 입력 프레임은 버리고 인식 상태를 초기화합니다.
앱 메뉴의 제스처 상태에서 장치 연결과 첫 입력 수신을 구분하며, 연결·복귀·첫 입력은 시스템 로그에 남깁니다.

2026-09-27: 기존 프로세스의 화면 복귀 로그와 자동 재연결 누락을 확인했습니다. 빌드와 자동 테스트는 통과했습니다.
실제 장시간 대기 및 잠자기 이후 핀치 복구는 아직 실기 검증하지 않았습니다. 시스템 제스처 차단 기능은 추가하지 않았습니다.

## 잠자기 방지 (Caffein)

메뉴 막대 아이콘을 오른클릭하거나 Control-클릭한 뒤 메인 메뉴에서 잠자기 방지 모드를 바로 선택합니다.

- `Off`: 잠자기 방지를 끕니다. 앱 시작 시 기본값입니다.
- `Prevent Sleep`: 유휴 상태의 시스템 잠자기를 방지하며 화면 꺼짐은 허용합니다.
- `Prevent Sleep and Display Sleep`: 유휴 상태의 시스템 잠자기와 화면 꺼짐을 모두 방지합니다.

활성화 중에는 기존 격자 아이콘 옆에 가운데 점과 커피잔을 표시합니다. 선택 모드는 체크 표시와 툴팁으로 확인합니다.
Caffein 프로젝트의 IOKit 전원 요청 방식을 Objective-C로 옮겼으며, 시스템 전원 설정을 수정하지 않습니다.
앱 종료 시 자체 요청을 해제하며 모드는 저장하지 않습니다. 수동 잠자기나 덮개 닫기로 인한 잠자기를 차단하는 기능은 아닙니다.

2026-10-27: `./build.sh`와 `./test.sh`가 통과했습니다. 자동 테스트는 실제 IOKit 요청의 종류·개수·활성 상태, 반복 선택, 모드 전환 및 객체 해제 시 요청 정리를 검증합니다.
메뉴 막대 아이콘의 실제 화면 배치와 장시간 유휴 상태에서의 잠자기·화면 꺼짐은 별도 실기 확인이 필요합니다.


## Caffein 장시간 검증 로그

`Advanced → Open Caffein Logs`에서 `~/Library/Logs/MiniLaunch`를 엽니다.
로그는 UTC 날짜별 `caffein-YYYY-MM-DD.jsonl` 파일이며 한 줄이 하나의 JSON 기록입니다.
기록할 때 오늘과 이전 6일의 파일을 보관하고 그보다 오래된 자체 로그 파일만 삭제합니다.
앱이 종료되어 있는 동안에는 정리하지 않습니다.

- `app_start`, `startup_state`: 앱 버전·빌드 번호·OS·프로세스 번호와 시작 상태
- `mode_requested`, `mode_applied`, `mode_failed`: 이전·선택 모드 및 적용 결과
- `assertion_create`, `assertion_release`, `assertion_rollback`: 전원 요청 종류·ID·IOKit 반환 코드
- `periodic_check`: 활성 상태에서 약 5분 간격으로 실제 OS 요청과 보유 요청을 비교한 결과
- `power_event`: 시스템·화면 잠자기 및 복귀 알림과 해당 알림 처리 시점의 요청 상태
- `app_exit`: 종료 시 요청 해제를 시도한 뒤의 상태

모드 번호는 `0 = Off`, `1 = Prevent Sleep`, `2 = Prevent Sleep and Display Sleep`입니다.
`matches: true`는 조회가 성공했고 자체 요청의 종류·개수·ID별 활성 상태가 일치한다는 뜻입니다.
`matches: false`이면 `query_result`, `owned_assertions`, `owned_checks`, `actual_assertions`를 함께 확인합니다.
`timestamp`는 기록 시각, `observed_at`은 전원 알림 수신 시각이며 UTC로 기록합니다.

주기 검사에는 최대 30초의 타이머 허용 오차가 있고 잠자기 중에는 실행되지 않습니다.
기록은 상태를 조회하기만 하며 요청을 자동 복구하거나 화면을 깨우지 않습니다.
강제 종료·충돌·전원 차단 시 `app_exit`가 없을 수 있으며, 알림과 요청의 존재만으로 실제 장시간 동작 성공을 단정하지 않습니다.
로그 쓰기·정리 오류는 시스템 로그에 남기며 잠자기 방지 자체는 계속 동작합니다.

각 모드를 설정된 유휴 시간보다 길게 유지하고 이후 수 시간 또는 하룻밤 시험합니다.
`Prevent Sleep`에서는 화면 꺼짐을 허용하면서 시스템이 유지되는지,
`Prevent Sleep and Display Sleep`에서는 화면도 유지되는지,
`Off` 및 앱 종료 후에는 자체 요청이 해제되는지 확인합니다.
다른 앱의 잠자기 방지 요청이 결과에 영향을 줄 수 있으므로 함께 확인합니다.

```sh
# 현재 전체 앱의 전원 요청을 확인합니다.
pmset -g assertions

# 검증 종료 후 시스템 잠자기·복귀 기록을 저장합니다.
pmset -g log > ~/Desktop/minilaunch-power.log
```

## 항목 메뉴와 Cursor 최근 폴더

앱을 오른클릭하거나 Control-클릭하면 `Reveal in Finder`와 `Uninstall with AppCleaner…`를 사용할 수 있습니다.
Finder에서는 ~/Apps의 alias가 가리키는 실제 앱을 선택합니다. AppCleaner에는 실제 앱 경로를 전달하여
관련 파일 분석 화면을 열며, 삭제는 AppCleaner에서 직접 결정합니다. 설치되지 않은 외부 앱의 메뉴는 비활성화합니다.
시스템 영역의 앱과 시스템 보호 표시(`restricted`)가 있는 앱에는 제거 메뉴를 표시하지 않습니다.
Finder alias와 심볼릭 링크의 실제 대상을 판별하며, Xcode처럼 별도로 설치한 Apple 앱을 번들 식별자만으로 제외하지 않습니다.
앱 Grid의 하위 폴더에서는 Finder 보기·열기와 iTerm 열기를 제공합니다.

첫 화면 하단에는 Cursor의 최근 목록 중 현재 존재하는 로컬 폴더만 최근 순서로 표시합니다.
각 디렉터리의 실제 Finder 아이콘과 이름을 표시하며, 사용자 지정 아이콘도 반영합니다.
폭을 넘으면 다음 줄로 이어지고 각 줄을 가운데 정렬합니다. 별도 스크롤이나 표시 개수 제한은 없습니다.
클릭 또는 방향키 선택 후 Return으로 Cursor에서 열고, 오른클릭 메뉴에서는
`Reveal in Finder`, `Open in Finder`, `Open in iTerm`을 사용할 수 있습니다. 전체 경로는 툴팁에 표시합니다.

Cursor의 `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb`를 시스템 SQLite로 읽기 전용 조회합니다.
파일·원격 폴더·없는 폴더·중복은 제외합니다. 이 저장 형식은 Cursor 내부 구현이므로 향후 변경될 수 있습니다.
앱 시작 시 백그라운드에서 미리 조회하고, 런처를 열 때는 메모리 캐시로 즉시 표시한 뒤 다시 조회합니다.
SQLite와 폴더 존재 확인은 메인 스레드에서 실행하지 않습니다. 디스크 캐시는 저장하지 않습니다.
목록이 바뀔 때만 화면을 갱신하고 등장 애니메이션과 오른클릭 메뉴 사용 중에는 갱신을 미룹니다.
키보드로 항목을 선택한 상태에서는 다음 열기나 ⌘R에서 최신 캐시를 반영합니다.
조회 실패 시 기존 캐시를 유지하고 정상 조회한 빈 목록은 반영합니다. ⌘R은 새 조회도 요청합니다.
